# Знание о системе пассажиропотока и мониторинга автопарка

## 1. Общая информация

Есть автопарк из **100+ автобусов**. Количество автобусов будет увеличиваться, поэтому система должна быть:

- масштабируемой;
- удобной для сопровождения;
- надежной в реальных условиях эксплуатации общественного транспорта.

На каждом автобусе установлено оборудование для:

- подсчета пассажиропотока;
- мониторинга работоспособности оборудования;
- получения информации о состоянии дверей;
- удаленного подключения и обслуживания;
- передачи данных на сервер через API;
- GPS/ГЛОНАСС-мониторинга транспорта.

Система работает в реальных условиях эксплуатации общественного транспорта, поэтому важны:

- надежность;
- автоматическое восстановление после сбоев;
- удаленная диагностика;
- минимальное ручное обслуживание.

---

## 2. Оборудование на автобусе

На каждом автобусе установлены следующие основные компоненты.

---

### 2.1. Бортовой компьютер Atom

**Кодовое название:** `atom`

`Atom` — это бортовой ПК, установленный в автобусе.

На нем установлена операционная система **Linux**.

На `Atom` работает программное обеспечение на **Python**, которое отвечает за:

- подсчет пассажиропотока;
- обработку событий открытия и закрытия дверей;
- получение данных от оборудования;
- мониторинг работоспособности системы;
- передачу данных на сервер через API;
- удаленный доступ через FRP;
- локальную обработку и, возможно, временное хранение данных при отсутствии связи.

У `Atom` есть:

- два LAN-порта:
    - `enp2s0`;
    - `enp4s0`;
- интернет-модем с SIM-картой;
- подключение к `signal` через RS-232.

---

### 2.2. Navtelecom SIGNAL

**Кодовое название:** `signal`

`Signal` — это ГЛОНАСС/GPS-трекер **Navtelecom SIGNAL**, установленный на автобусе.

Он используется для:

- мониторинга местоположения транспорта;
- получения сигналов от датчиков открытия/закрытия дверей;
- преобразования входных электрических сигналов в специальный протокол;
- передачи данных в `Atom` через RS-232.

К `Signal` подключены датчики дверей.

---

### 2.3. Двери и датчики

На каждом автобусе установлено **3–4 двери**.

У каждой двери есть датчики открытия и закрытия. Датчики подключены к `Signal`.

---

## 3. Схема взаимодействия компонентов

Упрощенная логика работы:

```
Двери автобуса
   ↓
Датчики открытия/закрытия
   ↓
Navtelecom SIGNAL
   ↓
RS-232
   ↓
Atom Linux PC
   ↓
Python software
   ↓
API
   ↓
Сервер
```

## 4. Программное обеспечение на Atom

На каждом `Atom` установлено Python-приложение.

Основные задачи приложения:

### 4.1. Подсчет пассажиропотока

Приложение отвечает за подсчет пассажиров, входящих и выходящих из автобуса.

---

## 5. Удаленный доступ

Для удаленного подключения используется **FRP**.

---

## 6. Сеть и интерфейсы

`Atom` имеет два LAN-интерфейса:

- `enp2s0`;
- `enp4s0`.

Также используется интернет-модем через SIM-карту.

---

## 7. Запуск Python-приложения

Python-приложение на `atom` запускается через связку:

```
uv + systemd
```

`uv` используется для управления Python-окружением, зависимостями и запуском приложения.

`systemd` используется для:

- автозапуска приложения после включения `Atom`;
- перезапуска приложения после падения;
- контроля статуса сервиса;
- просмотра логов через `journalctl`;
- управления жизненным циклом приложения.

---

## 8. Локальное хранение данных

На каждом `atom` используется локальная база данных:

```
SQLite
```

`SQLite` используется для хранения данных на борту автобуса, особенно при отсутствии интернет-соединения.

Если интернет пропадает на несколько часов:

1. Python-приложение продолжает собирать данные.
2. Данные сохраняются в локальную SQLite-базу.
3. События пассажиропотока, дверей и мониторинга не должны теряться.
4. Когда интернет появляется снова, приложение отправляет накопившиеся данные на сервер.
5. После успешной отправки данные помечаются как отправленные или удаляются из очереди, в зависимости от текущей реализации.

При восстановлении интернет-соединения `Atom` должен отправлять все накопившиеся данные на сервер.

---

## 9. Обновление Python-приложения

На `Atom` есть `systemd`-сервис, который отвечает за обновление Python-приложения.

Этот сервис:

- запрашивает обновления из Git;
- обновляет код программы;
- обновляет зависимости через `uv`, если требуется;
- перезапускает приложение после обновления;
- позволяет централизованно обновлять программу на **100+ автобусах**.

Общая логика обновления ПО:

```
systemd update service
        ↓
Проверяет Git-репозиторий
        ↓
Загружает новую версию
        ↓
Обновляет Python-приложение
        ↓
Обновляет зависимости через uv
        ↓
Перезапускает основной сервис
```

---

## 10. Обновление системных компонентов

Если нужно обновить не только Python-приложение, но и:

- системные конфиги;
- дополнительные программы;
- настройки Linux;
- системные сервисы;
- зависимости ОС;
- сетевые настройки;
- FRP;
- `systemd` unit-файлы;
- структуру директорий;
- базовые пакеты;

то используется ручной эталонный процесс.

---

## 11. Текущий процесс обновления образа

Текущий процесс:

1. На одном `Atom` вручную обновляются все нужные конфиги, файлы, программы и системные настройки.
2. Этот `Atom` становится эталонным образом.
3. ОС копируется через **Clonezilla**.
4. Полученный образ устанавливается на остальные `Atom`.

Это удобно для массового развертывания одинаковой базовой системы, но важно учитывать уникальные данные каждого автобуса.
